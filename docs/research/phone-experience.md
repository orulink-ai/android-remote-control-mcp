# PI 手机经验辅助：同一 App 任务族 v1

日常 `pi-phone` 已增加参数化的小红书任务：自然语言明确给出搜索词、目标帖子和点赞/收藏要求后，每一步由 Jev 根据当前界面候选判断。已验证示教提供简短经验；当前任务和实时观察决定执行内容。

这是有限中文解析与小红书 AX 适配的同 App 任务族 v1。它支持换搜索词、换目标、增减互动项，不代表任意自然语言任务规划或跨 App 泛化，也没有速度收益的实机结论。

## 入口与授权

启动 `pi-phone`，确认使用 `phone-control / auto`，直接输入一条独立任务，例如：

```text
在小红书搜索“露营装备”，打开第一篇，只收藏
搜索“猫咪日常”，打开标题“午睡”的帖子，点赞和收藏
搜索“猫咪日常”，打开标题“午睡”作者“小林”的帖子，只收藏，不要点赞
搜索“露营装备”，打开第一篇，点赞后再取消点赞
```

目标可以是本次搜索结果的第一篇，或精确标题；标题目标可以另指定作者。第一篇从实时搜索结果确定，不绑定示教首帖；找到候选后还须验证详情身份。目标缺失、歧义、额外评论/发送/删除等操作或不支持的语句会拒绝，不扩大成通用任务。

内部任务约定如下，搜索词和标题均来自本次用户请求：

```json
{
  "kind": "experience",
  "goal": "本次用户原文",
  "appName": "小红书",
  "query": "露营装备",
  "target": {"kind": "first"},
  "desired": {"collected": true},
  "restoreAfter": false
}
```

`desired` 只包含明确授权的 `liked`、`collected` 字段：

| 用户要求 | 状态授权与结束条件 |
| --- | --- |
| 只收藏 | 仅 `collected=true`；点赞保持初次核实的状态 |
| 取消点赞 | 仅 `liked=false`；收藏不变 |
| 点赞和收藏 | 两项均为 `true`，回读确认后结束 |
| 点赞后再取消 | 先验证 `liked=true`，再验证 `liked=false` |

已经满足目标的字段跳过点击。默认 `restoreAfter=false`，完成后不会擅自取消；显式先操作再取消时才为 `true`，且 `desired` 只能包含 `true`。它表示最终取消本次指定的项目，不是恢复初始值：即使原先已点赞，用户要求“点赞后取消”时最终也必须为未点赞。单项和双项均可，混合或不明确的撤回要求拒绝。

普通自然请求优先进入 `experience`。`/phone-replay`、对应固定别名及明确授权的旧固定录制命令仍走 legacy `skill-auto`；它们继续执行固定示例。Skill 正文不能充当新用户授权。读屏、打开 App、仅搜索的既有入口继续保留。

## 决策与经验的边界

```text
用户原文 → experience_tasks：解析本次参数和授权
         → ExperienceRuntime：读取当前 AX/截图，构造安全候选与验证状态
         → ExperiencePolicy：添加可选经验，交给 DecisionPolicy(jev-auto)
         → PI phone_action：派发本次选择 → 本项目 Android MCP → 回读验证
```

经验从当前终端 profile 的 `recipe` 路径加载，沿用已验证配方的来源与摘要校验。`experience_skill.py` 提取真实示教的短语义过渡，例如“搜索输入页 → 输入 → 结果页”或某互动字段的布尔变化，再按当前界面提供少量示例与建议。它们标记为仅供参考，不向模型导出历史节点 ID、坐标、搜索词、帖子标题或固定动作序列，也不作为本次成功断言。

每一步模型决策仍使用当前观察和完整的当前安全候选。经验不选择动作，不推进配方游标，不派发手机操作；新引擎的 `recipeHits` 为零。页面不同可以偏离示教，目标状态已满足则由实时验证结束，不为“学过这个步骤”而重复点击。

使用 `PI_PHONE_PROFILE` 指定的同一终端 profile；默认是 `~/.config/orulink-phone/terminal.json`。其中 `experienceEnabled` 默认 `true`，设为 `false` 可作无经验基线，仍使用同样的实时任务控制器与 Jev 决策。没有配置 `recipe` 时可正常走无经验 Jev；配置了无效配方会明确拒绝，不静默当成未配置。修改 profile 后启动新终端会话。

全部手机操作通过本项目 `watcher_android` LAN HTTP MCP；这条链路不调用 ADB。PI 的真实 `phone_observe` / `phone_action` 工具循环负责推进，策略内部不控制手机。Jev 超时、请求失败或非法选择沿用 `DecisionPolicy`：先返回刷新标记，必须由 PI 获取新的观察后，才允许 DeepSeek 兜底一次；DeepSeek 再失败则停止。BLOCKED、取消、投递不确定和验证失败不能借经验绕过。

## 与 App 录制生成的关系

App 录制 → 伴随服务 → PI 配对验证 → 编译 → 第二轮复用 → 发布，仍是原有固定示例范围。已发布的 verified source 现在也能作为新终端引擎的参数化经验来源；这不表示任意 App 录制都能生成通用技能，也不表示 App 的第二轮执行已经全部切换到新引擎。旧链路及其来源证据见 [App 闭环记录](app-workflow-loop.md)。

设计参考 [Record & Replay 官方说明](https://learn.chatgpt.com/docs/extend/record-and-replay) 与 [Build skills 官方说明](https://learn.chatgpt.com/docs/build-skills)：演示可以整理为新任务可用的上下文，技能说明指导执行并按需使用脚本。本项目当前采用已验证示教的语义经验加实时模型判断，未声称复刻官方内部实现。
