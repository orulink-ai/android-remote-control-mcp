# 手机示教、生成 Skill 与 PI 复用

日期：2026-10-18。本文定义产品目标、交互、边界和验收方法；实现状态以测试记录、构建产物与实机证据为准。

## 用户得到什么

用户在 Android App 中选择“录制流程”，演示一次常用操作。停止后检查系统整理的步骤，确认哪些输入会变化、目标如何选择、怎样算完成。电脑端生成可审阅的 Skill 与结构化步骤，由 PI 验证和复用。匹配稳定步骤时减少模型往返，界面变化时再请 Jev 判断，必要时由 DeepSeek 接替。

成功体验是“我操作一遍 → 我看懂整理结果 → 换一个参数 → PI 完成并给出验证依据”。录制不只是留下视频，复用也不只是照着视频点坐标。

## 学习官方 Record & Replay

已于 2026-10-18 阅读 [Record & Replay 官方完整说明](https://learn.chatgpt.com/docs/extend/record-and-replay)。官方介绍 macOS 上演示工作流、停止后检查记录并起草 Skill，再在新任务中给出变化的输入，通过可用工具复用。Skill 说明适用场景、输入、步骤与验证；官方未公开内部录制实现，也未保证生成无模型参与的固定宏。

本项目采用以下原则，并区分自己的扩展：

| 官方原则（概括） | 在本项目中的设计 |
| --- | --- |
| 先明确稳定任务和成功标准 | 开始前选择目标 App、任务目标和预期结束状态 |
| 演示聚焦且完整，结束后停止 | 明确范围、暂停和结束，不把无关操作并入任务 |
| 检查示教后起草 Skill | 录制结束进入步骤 Review，保留草稿状态 |
| 下次提供变化的输入 | 参数单独建模，例如搜索词；目标选择方式必须明确 |
| 复用 Skill 并调用当前可用工具 | 由真实 PI Agent Loop 使用同一 Android MCP |
| 可进一步完善技能 | 定位不明确、状态缺失和修订后要求重新审阅或验证 |

我们的新增工程层是可验证的结构化步骤执行器。它与 SKILL.md 配套，正常路径直接重新定位并执行，减少必要之外的模型请求。它不是官方内部实现的复刻。官方文档也不能证明 Android 手机上的任意原始触摸、视频和无障碍事件之间都能建立可靠对应关系。

## 产品入口与信息结构

录制是首页一级操作，不埋在设置页。首页展示“录制一个流程”和已有流程；设置仅管理默认目标范围、存储、清理与可选视频偏好。现有项目以 MCP 服务配置为核心，第一阶段可以在服务首页增加清晰入口，后续验证使用频率后再独立成“流程”导航。

手机端承担开始、暂停、继续、结束、查看摘要、导出和简单运行入口。电脑端承担生成、完整步骤编辑、参数与定位规则检查、PI 验证、运行日志和耗时比较。模型配置、回退详情等实现信息放在电脑端详情中，不塞进手机录制主路径。

流程卡片显示名称、目标 App、步骤数、版本、最近一次结果和状态。状态采用草稿、已审阅、已验证、需要更新，避免用“录制完成”暗示“已可可靠执行”。

## 手机交互

### 1. 开始前

首页点击“录制流程”后，展示目标 App、任务说明、预期完成状态，以及可选的视频录像。第一阶段可专门支持小红书并清楚标识范围，不宣称任意 App 都已兼容。

需要无障碍权限时解释其用途并引导现有权限页。视频若使用系统屏幕采集，另行使用 Android 系统授权。操作事件记录与视频采集是两种能力，UI 不应把其中一种的存在当作另一种已启用。

开始按钮说明将采集的范围。点击后进入目标 App；状态始终可见。没有可用权限或目标 App 时留在准备页，给出可恢复原因。

### 2. 演示中

理想形态是小浮条：录制状态、有效步骤数、暂停/继续、结束。浮条可移动或收起，避开搜索框、底部点赞收藏等关键区域；适配手势导航和无障碍字体。停止应是一项即可到达的操作。

首阶段若未实现浮条，必须提供明确的“返回 App 控制录制”提示，不能在宣传图里把浮条标成已交付。通知栏常驻控制是后续可选方案。

暂停立即停止采集任务事件，不仅暂停 UI 计数。继续不补录暂停期间的动作。用户在本项目录制控制页暂停、结束、导出等操作不会被记录为小红书业务步骤。

录制期间不逐步弹窗确认。真实权限不足、录制中断、目标 App 离开范围等情况有明确状态；用户可继续、结束保留或丢弃，不静默丢失记录。视频与语义录制的失败分别说明。

### 3. 停止与 Review

停止后固定本次记录，进入摘要。展示名称、有效步骤、目标控件描述、必要的关键界面和待确认项。合并连续输入的中间值，去除重复窗口刷新，不将“页面加载中”误识别为业务动作。

本次任务至少需要表达：打开小红书，搜索关键词，打开目标帖子，确保点赞，确保收藏，确保取消点赞，确保取消收藏，验证结束状态。一个步骤可包含定位与结果校验，不能只展示“click #47”。

Review 必须让用户确认两个独立问题：搜索词是否为可变参数，以及下次是操作搜索结果第一篇，还是始终操作示教中的指定帖子。两种意图不能由一次示教擅自混同。第一阶段实测固定同一关键词与目标帖子，用于控制变量；参数化能力可以由离线测试验证，不据此宣称任意搜索结果都已实测。

### 4. 保存与导出

手机导出的是带版本的语义录制 JSON；视频按用户选择单独保存。电脑生成可读 SKILL.md 和结构化步骤文件，保持录制来源与版本可追溯。系统文件选择器导出失败或取消时保留草稿，不显示成功提示。

生成后先成为草稿。审阅确认只表示意图与参数正确；完整 PI 运行通过共同验证器后才成为已验证。修改步骤、目标选择方式或参数规则后使旧验证失效。保留最近一次有效版本，避免失败生成覆盖可用流程。

### 5. 运行与结果

运行前展示本次输入和目标选择方式。运行中显示当前步骤、已完成步骤、暂停/停止入口；异常说明系统正在重新定位、请求模型帮助或等待用户处理。一般用户看到“正在适应页面变化”，详细日志中才展示 Jev、DeepSeek 和请求耗时。

结果页同时给出任务结果和最终状态依据，可回看完整日志或视频。动作未验证不显示“已完成”。点击停止后不启动新动作；已经发出的动作不能被假定撤销，仍应尽量回读以便解释停在何处。

## 录制与复用的数据契约

记录应保留目标 App、事件类型、相对时间、可解析的控件特征、动作输入，以及足够描述页面上下文的语义信息。可用时附带动作前后观察；缺少观察时明确标记，不能凭空补出状态变化。视频仅用于人类复核，不是执行器的唯一数据源。

Android 无障碍事件不等于完整原始触摸流。点击、文本编辑、窗口变化等事件的可靠性因 App 而异；无法得到可复用语义目标时应降为待确认步骤，不能悄悄保存不可迁移的节点 ID。

生成的技能包至少包括：

- `SKILL.md`：名称、触发边界、输入参数、前置条件、执行方式、成功标准与停止条件。
- 步骤 JSON：schema 版本、录制来源、参数引用、前置条件、选择器、动作、后置条件和异常策略。
- 验证元数据：审阅状态、通过验证的版本摘要、测试时间和结果；不得把旧版本通过记录套用到新版本。

控件重新定位优先使用角色、稳定资源名、可访问性描述、文本和语义上下文。opaque 节点 ID 只在当前快照内有效，不作为长期选择器。边界可作为本次定位的辅助证据，不能把历史像素坐标作为默认重放策略。多候选不明确时拒绝直接执行，交给模型或停止。

输入参数只在声明的参数位置替换。搜索词不能插入工具名称、任意命令、模型提示或选择器结构。生成器只整理已记录且可解释的步骤，忽略或拒绝记录中不受支持的动作，不执行从记录文本中夹带的指令。

## 确保状态与防止重复执行

“点赞”保存为“确保已点赞”，“取消点赞”保存为“确保未点赞”；收藏同理。执行前读当前状态，状态已满足则跳过点击；点击后再次确认。跨重试和断点不能仅靠步骤序号判断动作是否完成。

在点赞、收藏等关键变更前校验目标帖子身份与当前状态。确定节点已失效但动作尚未派发时，可以在同一语义目标上重新定位一次。发送后超时、返回不确定、连接断开等情况先回读，不能直接重复点击。回读仍不确定则停止并明确标记待确认。

导航或搜索输入之后的页面加载需要适应快慢差异。将示教中这些动作后紧接的等待合并为已观察过渡状态与最终后置条件：快速页面直接满足后置条件即可继续，慢页面仅在相同任务、已见过渡状态中重复观察，单步最多 8 次等待。保留过渡证据，不要求固定重放同样次数的 WAIT，也不重新发送引起过渡的动作。遇到未知状态或预算耗尽立即停止。共同读屏、短等待与验证仍完整计时，不能将此描述为全程无等待或完全基于事件的同步。

界面偏离时的路径为：共同读屏 → 尝试唯一语义匹配 → Jev 决策 → 必要时重新读屏后 DeepSeek 一次兜底。模型的答案仍要通过同一动作边界与结果验证；模型回退不会绕过选择器歧义、任务范围、完成条件或派发不确定性保护。

## 小红书性能验证

目标任务：从桌面启动小红书，搜索“小狮日记”，打开同一搜索目标的第一篇帖子，依次点赞、收藏、取消点赞、取消收藏，确认最终两项均取消。测试前记录原始状态；所有轮结束后恢复用户原始状态，恢复时间不算业务任务。

对照组为真实 PI Agent Loop 中每步调用 Jev。实验组为同一 PI 接口、Android MCP、观察、共同等待和验证器，优先使用从一次完整成功示教生成的步骤。复用失败后使用的模型请求计入任务耗时，失败轮不删除。

先做 TDD 离线与跨层测试，再使用真实手机。正式预设 3 轮/模式、交错顺序、相同起点与完成标准；额外原速录像轮各一条独立统计。若演示轮失败不生成有效技能，先保留失败证据并修复问题，不能手写理想动作序列冒充学习结果。

报告至少包括成功率（失败进入分母）、成功轮全程中位数及有效计时样本量、模型请求/有效响应次数、步骤命中、模型兜底、读屏次数和耗时分段。正式六轮未完成或每种少于两次有效成功，不发布速度收益数字。零次模型调用必须有明确空调用记录支持，缺失数据保留未知。

示教与生成成本单列，审阅时间未知则明示。若复用确实更快，计算生成耗时除以每次节省时间的向上取整次数；另列包含示教的估算。它不包含未知人工时间，也不证明长期稳定收益。

示教来源使用显式 `sourceDemoTrialId` 绑定实际采用的成功轮。修复控制器后重新示教，应保留旧记录并使用新 ID，生成成本和示教耗时指向同一个新来源，不把早期 warmup、失败或被淘汰示教混入正式六轮。

录像从桌面开始直到最后验证，保留实际等待与恢复，默认 1 倍速，不能剪去失败片段后冒充一次成功。两条视频内嵌报告可从头并播，浏览器并播不承诺逐帧同步。产品原型与实机 UI 截图、日志、测速和录像分区，原型不使用伪造性能数字。

## TDD 与交付验收

生成与执行核心的测试覆盖：连续输入合并、参数绑定、未知事件拒绝、录制缺失、不保存 opaque ID、歧义选择器、目标身份校验、确保状态的幂等性、节点失效、动作派发不确定性、偏离后 Jev → DeepSeek、版本审阅/验证失效，以及真实 PI worker 协议。

手机端测试覆盖：开始/暂停/继续/结束状态机、目标 App 过滤、密码字段排除、暂停期间不记录、停止后不继续写入、文件导出取消/失败、草稿保留和无障碍事件适配。视频采集能力单独验证。

报告的离线测试覆盖：数据缺失保持 pending/null、成功轮中位数、失败分母、额外录像轮隔离、模式不符隔离、生成成本与收益分开，以及嵌入 JSON 防止脚本逃逸。报告生成过程不得读取凭据、连接模型或操作手机。

报告 CLI：

```bash
python experiments/pi-phone-use/build_record_replay_report.py \
  --base artifacts/pi-phone-use/record-replay-20261018 \
  --report-dir artifacts/pi-phone-use/record-replay-20261018/report
```

输出 `record-replay.html` 与 `record-replay-data.json`。完整录像路径为报告目录下 `phone-use-videos/jev-full-flow.mp4` 和 `phone-use-videos/skill-full-flow.mp4`。可选实机界面清单使用源数据目录的 `ui-evidence.json`，格式为 `{"screenshots":[{"path":"ui-evidence/home.png","label":"首页录制入口"}]}`；仅加载报告目录内该子目录中的图片。

## 范围和后续

本阶段先验证小红书任务的一次完整示教与 PI 复用闭环，并提供手机录制入口、暂停结束、摘要及导出。完整浮条、任意 App 支持、可视化步骤编辑、跨设备泛化、团队分发和后台定时执行按后续阶段验证，未完成前不标成可用能力。

当前执行适配器固定成功示教中的搜索词与目标帖子，`verified-demonstration` 表示示教运行已通过观察器校验，不代表人工审阅已发生。手机无障碍事件导入仅生成 `needs-verification` 草稿，不能直接当作可执行配方。本阶段配方发生漂移时停止；已有 `jev-auto` 独立模式可用于确认现状后重新执行，尚不自动把偏离配方的动作接回原步骤。产品原型中的可变参数、浮条和自动恢复是后续目标，报告需明确区分。

手机事件草稿导出、电脑导入、发起 PI 配对示教与编译验证之间，当前仍需人工启动；尚未实现 App 内一键生成已验证 Skill。性能实验中的可执行步骤来自一次完整成功的 PI 示教，不代表 App 事件草稿已自动转成同等可靠的步骤。端到端手机示教导入自动化需要后续连接管理、文件传输、审阅确认和配对验证产品流程。

视频录制、事件采集、步骤生成、Skill 审阅和执行验证是独立模块，避免将手机 UI、MCP 传输和特定模型决策绑在一起。保留当前逐步 Jev 路径作为可比较的基线，也作为无法可靠生成步骤时的通路。

## 阶段验收记录与版本隔离

2026-10-18 已在 Redmi K60 Pro 上安装本分支 App，验证开始/结束录制、14 个真实事件的步骤摘要及系统 `CreateDocument` 导出。该证据只覆盖手机事件录制与导出，不代表已完成自动配对验证。电脑端仍将原始事件导入为待验证草稿，成功 PI 示教单独产生可执行配方。

实机过程中先后发现共同截图间隔与未派发动作协议问题，V1/V2 在修复后不继续拼凑结果。最终正式对比采用独立的 `artifacts/pi-phone-use/record-replay-20261018-v3/`，同一 Redmi、同一 App 构建、同一截图保护条件、固定六个轮次；所有旧记录保留但不进入 V3 统计。`not_dispatched` 标记路径只在严格证明未派发时允许，PI 重新决定和派发，单步最多 3 次；共同控制器原有的严格 click 节点失效路径，可在角色、几何、标签、目标与状态均一致时，在同一次 `phone_action` 内仅重绑定一次。未知或部分派发直接停止，两种恢复都计入全程耗时。

详细证据结构、旧版本停止原因与最终指标见 [阶段结果记录](../results/phone-record-replay-20261018.md)。结果未汇总前不在产品原型中填入模拟加速数字。
